# [メール文作成 AI エージェント] 設計方針書

## 📋 概要

メール文作成 AI エージェントの設計方針を定義します。3 つのエージェント（情報収集、質問、文章作成）による段階的な処理と、LangGraph を使用した状態管理により、効率的で品質の高いメール文作成を実現します。

## 🔍 要件の分析

要件定義書から抽出した主要な実装ポイント：

- 3 つのエージェントによる段階的処理（情報収集 → 質問 → 文章作成）
- State クラスによる状態管理
- RAG による個人情報管理（JSON ファイル）
- レート制限対策（リクエスト間隔制御・エラー時再試行）
- 包括的なエラー処理（入力検証・LLM 応答検証・タイムアウト）

## 🛠 実装方針

### アーキテクチャ選択

**選択したアーキテクチャ**: 3 エージェント分離型アーキテクチャ

**選択理由**:

- 各エージェントが単一責任を持つことで、保守性と拡張性が向上
- 段階的な処理により、ユーザーの入力負荷を軽減
- エージェント間の明確な境界により、デバッグとテストが容易

### データフロー

```
ユーザー入力 → 情報収集エージェント → State更新
                ↓
            質問エージェント → ユーザー回答 → State更新
                ↓
            文章作成エージェント → RAG検索 → 最終出力
```

## 🔄 実装方法の選択肢と決定

### 選択肢 1: 単一エージェント方式

**説明**: 1 つのエージェントで全ての処理を行う
**評価**:

- メリット: 実装がシンプル、状態管理が容易
- デメリット: 責任が分散、保守性が低下、拡張性に制限

### 選択肢 2: 3 エージェント分離方式

**説明**: 情報収集、質問、文章作成を別々のエージェントで処理
**評価**:

- メリット: 単一責任原則、保守性向上、段階的処理でユーザビリティ向上
- デメリット: 実装が複雑、エージェント間のデータ受け渡しが必要

### 決定: 3 エージェント分離方式

**選択理由**:

- 要件の「段階的な処理」に最適
- 各エージェントの責任が明確で、将来の機能追加が容易
- ユーザーの入力負荷を軽減できる設計

## 📊 技術的制約と考慮事項

### State 管理

```python
class EmailState:
    email_type: str  # "new" or "reply"
    recipient_info: dict  # 送信先情報
    original_content: str  # 元メール内容（返信時）
    collected_answers: dict  # 質問エージェントで収集した回答
    current_step: str  # 現在のステップ
    personal_info: dict  # RAGから取得した個人情報
```

### エージェント設計

#### 1. 情報収集エージェント

- 責任: メール種類、送信先、元メール内容の収集（返信時は LLM による要約も）
- 入力: ユーザーの初期入力
- 出力: State 更新、次のエージェントへの移行

#### 2. 質問エージェント

- 責任: メール内容に関する質問生成と回答収集（元メールや送信目的に応じて動的に生成）
- 入力: State（元メール内容、送信目的）
- 出力: 質問生成、回答収集、State 更新

#### 3. 文章作成エージェント

- 責任: RAG 検索、最終メール文の生成（個人情報も活用）
- 入力: State（収集された情報）
- 出力: 最終メール文

### データ管理

- 個人情報: JSON ファイル形式で保存
- RAG: ベクトルデータベース（Chroma/FAISS 等）を想定
- 状態: State オブジェクト全体をエージェント間で共有

### パフォーマンス・エラー処理

- レート制限: リクエスト間隔制御（1 秒間隔）
- エラー処理: 再試行機能（最大 3 回）
- タイムアウト: 30 秒でタイムアウト処理
- 入力検証・LLM 応答検証を各ステップで実施

## ❓ 解決すべき技術的課題

1. エージェント間の状態同期
   - State オブジェクトの整合性確保
   - エージェント間のデータ受け渡しの最適化
2. RAG 検索の精度向上
   - 個人情報の適切なインデックス作成
   - 検索クエリの最適化
3. エラー処理の実装
   - 各エージェントでの適切なエラーハンドリング
   - ユーザーへの分かりやすいエラーメッセージ
4. 入力検証の実装
   - 各ステップでの入力形式チェック
   - 必須項目の確認と適切なプロンプト生成
